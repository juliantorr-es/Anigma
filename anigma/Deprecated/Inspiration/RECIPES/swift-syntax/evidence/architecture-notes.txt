# Architecture Notes: swift-syntax

## Core Design Principles

1. **Immutable Syntax Trees**: All syntax nodes are immutable value types, enabling safe sharing and caching.
2. **Arena Allocation**: RawSyntax nodes are allocated in arenas for performance and memory efficiency.
3. **Visitor Pattern**: Double-dispatch via generated visitor methods for type-safe traversal.
4. **Rewriter Pattern**: Subclassable SyntaxRewriter for transforming syntax trees with minimal copying.
5. **Source Location Mapping**: AbsolutePosition and SourceLocationConverter for precise source mapping.
6. **Incremental Parsing**: ParseTransition for reusing unchanged parts of syntax trees.
7. **Diagnostic Framework**: Structured diagnostics with FixIts for suggested changes.

## Key Patterns to Adapt

### AST Lens Service
- **Queryable AST Views**: SwiftSyntax provides `SyntaxProtocol` with `children`, `parent`, `ancestors`, `descendants`.
- **Location-based Lookup**: `SourceLocationConverter` converts line/column to `AbsolutePosition`.
- **Caching Strategy**: `IncrementalParseTransition` caches parsed trees for unchanged files.
- **Thread Safety**: Syntax trees are immutable and thread-safe; parsing is not.

### Rewrite Rule Protocol
- **SyntaxRewriter Base Class**: Override `visit` methods to transform specific node types.
- **Idempotent Transformations**: Rewriters can be applied multiple times safely.
- **Change Tracking**: `SourceEdit` records precise changes (old range, new text).
- **Composition**: Multiple rewriters can be chained; order matters.

### Receipt-Based Rewriting
- **Diagnostic Reporting**: Every transformation can emit `Diagnostic` messages.
- **FixIt Suggestions**: `FixIt` provides suggested edits with source ranges.
- **Evidence Collection**: `SourceEdit` can be collected into a "receipt" of changes.
- **Validation**: Apply changes, verify round-trip, generate hash of before/after.

## Governance Integration Points

### Policy Enforcement
- **Trust Tiers**: Different rewrite rules require different trust levels (bronze, silver, gold, platinum).
- **Harmonia Validation**: All AST transformations must pass Harmonia's policy checks.
- **CCTV Events**: Each rewrite generates audit events with before/after state.
- **Accessum Signing**: Transformation receipts cryptographically signed by Accessum.

### Contract Boundaries
- **ASTLensProtocol**: Queryable AST views with caching and location lookup.
- **RewriteRuleProtocol**: Idempotent transformation rules with trust tier requirements.
- **TransformationReceiptProtocol**: Signed evidence of transformations with hash chain.
- **SyntaxAnalysisContract**: Existing contract for syntax analysis (needs extension).

## Risks and Mitigations

### Code Copying Risk
- **DO NOT COPY**: SwiftSyntax library dependencies, parsing pipelines, source file readers.
- **DO NOT COPY**: Swift compiler integration, build system hooks.
- **REIMPLEMENT REQUIRED**: AST tree structure as AnigmaCore entities, transformation logic as ECS systems.

### Performance Risk
- SwiftSyntax is optimized for compiler use; our adaptation may be slower.
- Mitigation: Use caching, incremental updates, and arena allocation patterns.

### Governance Risk
- AST transformations are powerful; must be tightly controlled.
- Mitigation: Strict trust tiers, Harmonia validation, signed receipts.
