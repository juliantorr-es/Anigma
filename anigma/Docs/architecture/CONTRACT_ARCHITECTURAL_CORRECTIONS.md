# Contract System: Required Architectural Corrections

This document tracks the four "Dire Adjustments" required to align the Anigma contract system with the project's constitutional boundary model and hardware-saturated throughput goals.

## Status: Roadmap (Tracked via TD-12aa9d)

### 1. The Serialization Wall (Payload-Reference Compliance)
**Issue:** [td-2ded3a]
**Problem:** `SaturatedSearchContract` and others in `ContextumModule` use direct `[Float]` payloads in their inputs. This violates the "Serialization Wall" intended by `PayloadReferenceCompliantContract`.
**Correction:** 
- Refactor `SaturatedSearchContract` to implement `PayloadReferenceCompliantContract`.
- Replace direct payload fields with `IndirectPayloadReference` (Binary Atlas / mmap).
- Add validation to reject inline bulk payloads where indirect references are required.

### 2. Protocol Unification (AnigmaContract)
**Issue:** [td-24c7c7]
**Problem:** Split between `WorkflowContract` (IR/CoreML) and `ContractSpec` (Execution/Saturation).
**Correction:**
- Unify into a single `AnigmaContract` hierarchy.
- Hierarchy must capture: Identity/Versioning, Static Invariant Validation, Execution Hook, and Output Validation.
- Update IR/CoreML/Execution contracts to the new common model.

### 3. Active Governance (MissionPrivacy Gate)
**Issue:** [td-894a50]
**Problem:** `MissionPrivacyContract` is a passive struct, making it difficult to enforce as an active, auditable gate.
**Correction:**
- Wrap `MissionPrivacyContract` in a proper `ContractSpec` or `WorkflowContract`.
- Encode the `regulated-decision` rule: ensure configurations requiring human review cannot be bypassed.
- Keep Tier 1 pure: validation returns decisions/errors, not side effects.

### 4. Deterministic Schema Hashing
**Issue:** [td-ec94fe]
**Problem:** "Fake" literal hashes (e.g., "v1.0") poison boundary integrity and versioning detection.
**Correction:**
- Implement a schema hashing utility.
- Derive hashes deterministically from canonical schema descriptions.
- Prohibit hardcoded version strings in `ContractID.schemaHash`.

## High Priority: Full-Stack Contract Formalization
**Issue:** [td-af05c4, td-c24fdf, td-d18a06, td-8eb1ef]
**Requirement:** Governance must extend beyond compute capsules to cover the entire system stack. The following layers are currently using ad-hoc protocols and must be migrated to the `AnigmaContract` model.

### 1. System Core Contracts (Cores)
- **Target:** `HardwareAuthority`, `DatabaseCore`, `StorageCore`.
- **Goal:** Formalize critical system-effect boundaries. Every database migration, hardware capability grant, or storage vault access must produce an auditable receipt.

### 2. Module Interface & Lifecycle Contracts (Modules)
- **Target:** `AccessumModule`, `VectorumModule`, `ContextumModule`.
- **Goal:** Standardize cross-module communication. Replace internal protocols (e.g., `EmbeddingComputing`) with formal `WorkflowContracts` that enforce versioning and serialization walls.

### 3. UI Data Binding & Interaction Contracts (UIs)
- **Target:** `AnigmaUI`, `StudioView`, `ContractDashboard`.
- **Goal:** Govern the view-to-model boundary. Interaction evidence (e.g., a user manually overriding a regulated decision) must be captured via a contract to ensure evidence-chain integrity.

### 4. Daemon & Service Lifecycle Contracts (Lifecycles)
- **Target:** `AnigmaDaemon`, `ServiceLifecycle`.
- **Goal:** Formalize process-level state transitions. Startup, shutdown, and recovery sequences must be deterministic and logged as contract-validated artifacts.

## The "Anigma Production Standard": Five Hardening Lanes
**Issue:** [12aa9d Roadmap Expansion]

To transition from "well-behaved code" to "physical system constraints," the following five hardening lanes are required:

### 1. Hardware-Locked Evidence Rings (Lane 1)
**Goal:** Prevent evidence loss.
- **Requirement:** `loggingRing` must be a mandatory, fixed-size `mmap` buffer.
- **Interlock:** Final `ContractReceipt` must incorporate a truncated hash of the entire ring state.

### 2. Zero-Copy Enforcement (Lane 2)
**Goal:** Prevent runtime payload leakage.
- **Requirement:** Prohibit Swift `Array`, `String`, and `Dictionary` in `.inference` lane inputs.
- **Enforcement:** Boundary linting and use of `RelativePointer<T>` for type-safe offsets in `NativeWire`.

### 3. Governance Kill-Switches / Interlocks (Lane 3)
**Goal:** Make the "Constitution" physical.
- **Requirement:** Failed `MissionPrivacyContract` verification must trigger a hard-abort or `Signal 4` (Illegal Instruction) on the target Hardware Lane.
- **Gate:** Block pipeline execution until a `HumanReviewReceipt` is present for regulated decisions.

### 4. Tamper-Evident Artifact Store (Lane 4)
**Goal:** Protect boundary integrity on disk.
- **Requirement:** All artifacts must be wrapped in a `SignedArtifactEnvelope` cryptographically tied to the `ContractReceipt`.
- **Integrity:** Use Merkle-tree verification (e.g., `fs-verity`) for all `BinaryAtlas` hot-path reads.

### 5. Deterministic Resource Budgets (Lane 5)
**Goal:** Protect "The Machine" from noisy neighbors.
- **Requirement:** Every contract defines a `maxMemoryFootprint`.
- **Enforcement:** Pre-allocate in dedicated `MemoryArena`; hard-kill tasks upon violation.
