## 2. Pillar 1: The Three-Tier Integration Surface

Anigma follows **ADR-0006 (Three-Tier Architecture)**. The Integration Surface defines how Tier 3 (Capability Modules) interact with Tier 2 (Platform Runtime).

### 2.1 The Governed Write Loop
Every mutation (Database, Artifact, Execution) MUST follow the Governed Write Loop:
1.  **Proposal**: `WriteProposal(principal, operation, entity, context)`
2.  **Decision**: `GovernanceController.canWrite(proposal) -> WriteGateDecision`
3.  **Execution**: Native operation on underlying resource (PostgreSQL, NVMe).
4.  **Evidence**: Signed `CoreReceipt` generated by `EvidenceAuthority`.

### 2.2 Protocol-First Authorities
All Tier 2 resources are accessed via stable protocols (Authorities). Tier 3 modules never touch actors directly; they interact through the `RuntimeServicesProxy`.

| Authority | Responsibility | Integration Target |
| :--- | :--- | :--- |
| **`DatabaseAuthority`** | Governed SQL & RLS | PostgreSQL |
| **`EvidenceAuthority`** | Verifiable Receipt Sink | `audit_logs` table |
| **`ArtifactAuthority`** | Content-Addressed Storage | NVMe / S3 |
| **`HardwareAuthority`** | GPU/ANE Compute & Routing | Metal / CoreML |
| **`InferenceAuthority`** | Multi-Model Execution | MLX / Llama.cpp |
| **`ExecutionAuthority`** | Workflow & Job Orchestration | `JobStore` |

## 3. Pillar 2: Canonical Identity and Provenance Hierarchy

To prevent ID drift across modules, the platform standardizes on a single hierarchical identity and provenance stack.

1.  **`ProjectID`** (Tenant): Top-level institutional boundary (RLS isolation unit).
2.  **`PrincipalID`** (Identity): The originator of the request (human or agent).
3.  **`SessionID`** (Interaction): A continuous interaction window (for example, a specific chat).
4.  **`RunID`** (Task): A specific execution of a workflow or job.
5.  **`EpisodeID`** (Segment): A logical provenance segment within a long-running session.

**Rule**: Every `CoreReceipt` and `TelemetrySpan` MUST include the `ProjectID` and `RunID` at minimum.

## 4. Pillar 3: Unified Evidence Plane (Audit vs. Telemetry)

Anigma distinguishes between **hash-chained governed evidence** and **redacted telemetry**.

| Attribute | **Audit Receipts (Governance)** | **Telemetry Spans (Observability)** |
| :--- | :--- | :--- |
| **Fidelity** | 1:1 complete record | Sampled (1-100%) |
| **Privacy** | High (high-fidelity, encrypted) | Redacted (hashed, no user strings) |
| **Storage** | PostgreSQL (`audit_logs`) | OSLog / File / Memory |
| **Verification** | Cryptographically signed and hash-chained | Aggregate statistics |
| **Path** | Governed write loop | `TelemetryClient` pipeline |

The evidence plane is the bridge between the kernel boundary and the verifier lane: hash-chained audit receipts prove governed writes, and telemetry supports evidence-backed evaluation.

## 5. Pillar 4: Hardware Saturation Spine

The platform maximizes Apple Silicon via specialized "Hardware Lanes" and zero-copy memory.

### 5.1 Hardware Lanes
Workloads are assigned to lanes based on hardware affinity:
-   **Control Lane (CPU)**: Governance, Auth, State management.
-   **Inference Lane (GPU)**: Massive tensor operations, Chat, Image Gen.
-   **Perception Lane (ANE)**: Background OCR, Document Layout, Embeddings.
-   **Native Lane (CPU/SIMD)**: Deterministic fallback and low-latency math.

### 5.2 Unified Buffer Pool
The `HardwareAuthority` provides page-aligned, shared memory buffers.
-   **Zero-Copy**: Swift orchestration hands a memory pointer to Metal; no buffer copying occurs.
-   **Backpressure & Load Shedding**: `AsyncStream` based handshakes ensure the CPU never overwhelms the GPU queue. When saturation exceeds 90%, the system triggers **Load Shedding**: dropping low-priority telemetry and background analysis to protect user-facing orchestration.

---

## 6. Pillar 5: Sidecar Connectivity & Security

Anigma supports a hybrid networking model to eliminate the "Sidecar Tax."

-   **Management Plane (gRPC)**: Standard gRPC for status, logs, and user auth.
-   **Data Plane (Cap'n Proto)**: Shared-memory IPC using Cap'n Proto for massive tensor handoffs between the App and ML Sidecar.
-   **Agent Checkpoint Protocol**: A turn-based protocol where agents publish reasoning state to a shared **Agent Blackboard** (Redis-backed) before context is compacted into long-term memory.
-   **Deterministic Audit Contract**: High-stakes reasoning paths utilize **Deterministic Execution Mode** (CPU/SIMD fallback) to ensure that receipts are reproducible and explainable regardless of hardware acceleration jitter.
-   **Zero-Trust Identity**: 
    -   **SPIFFE/SPIRE**: Workload identity for service-to-service auth (mTLS).
    -   **Baggage Propagation**: W3C Trace Context and Baggage flow through every async hop, ensuring a verifiable principal trail.

## 7. Strategic Gaps Resolved (Design Closure)

1.  **Identity Standardization**: All IDs now map to the hierarchy in Pillar 2.
2.  **Job Persistence**: `ExecutionAuthority` will now use a PostgreSQL `JobStore`.
3.  **Audit/Telemetry Conflict**: Resolved via the data plane split in Pillar 3.
4.  **Hardware Inefficiency**: Resolved via the Lane Scheduling in Pillar 4.
5.  **Networking Performance**: Resolved via Cap'n Proto + Shared Memory in Pillar 5.
