## 1. Overview
In institutional environments, "I don't know why the AI said that" is an unacceptable failure state. The Deterministic Security Audit design ensures that every high-stakes AI decision is reproducible, explainable, and cryptographically pinned to the exact hardware and policy context that produced it.

## 2. The Deterministic Audit Envelope

Every `CoreReceipt` generated by the `EvidenceAuthority` for a reasoning task MUST include the following **Determinism Metadata**:

| Field | Description | Purpose |
| :--- | :--- | :--- |
| **`policy_version_id`** | Hash of the `DoctrineRule` at time of execution. | Ensures policy consistency. |
| **`model_layer_checksum`**| BLAKE3 hash of the model weights and configuration. | Guards against model poisoning/drift. |
| **`hardware_target`** | `GPU` \| `ANE` \| `CPU/SIMD`. | Tracks the execution engine. |
| **`determinism_flag`** | `Strict` \| `Approximate`. | Indicates if the result is reproducible bit-for-bit. |
| **`seed_entropy`** | The specific random seed used for sampling. | Essential for replay reproducibility. |

## 3. Execution Fallback Rules

To balance **Hardware Saturation** with **Audit Integrity**, Anigma employs a tiered execution strategy:

### 3.1 Tier 1: Governed Reasoning (Strict)
*   **Workloads**: Legal advice, accessibility policy decisions, security audits.
*   **Hardware**: `Native Lane` (CPU/SIMD) or **Deterministic GPU Kernels**.
*   **Rule**: Result MUST be bit-for-bit reproducible on any compatible institutional node.
*   **Audit**: Signed receipt includes the full `Deterministic Audit Envelope`.

### 3.2 Tier 2: Assistive Reasoning (Approximate)
*   **Workloads**: Code formatting, drafting emails, creative brainstorming.
*   **Hardware**: `Inference Lane` (GPU) or `Perception Lane` (ANE).
*   **Rule**: Floating-point jitter is acceptable within a defined tolerance.
*   **Audit**: Receipt includes a `Non-Deterministic` flag and the hardware ID.

## 4. Hash-Chained Provenance

The `AuditChainSystem` (implemented in `GovernanceCore`) ensures that the sequence of decisions is immutable.

1.  **Turn-based Checkpoint**: Before an agent moves to the next sub-goal, it computes the `receipt_hash` of its current "Thought" + the `previous_receipt_hash`.
2.  **Verification**: Auditors can "Replay" the reasoning chain by initializing a fresh `InferenceAuthority` with the same `model_layer_checksum` and `seed_entropy` from the receipt.

## 5. Implementation Interface

```swift
public struct AuditEnvelope: Sendable, Codable {
    public let modelHash: String
    public let policyVersion: Int
    public let seed: UInt64
    public let hardware: String // e.g. "Apple M3 GPU"
    public let isDeterministic: Bool
}

public protocol AuditVerifiableAuthority: Authority {
    /// Replays a specific reasoning task to verify the receipt.
    func verify(receipt: CoreReceipt) async throws -> VerificationResult
}
```
