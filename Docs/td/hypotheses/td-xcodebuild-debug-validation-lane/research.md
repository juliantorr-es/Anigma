# td-xcodebuild-debug-validation-lane: Research

## Goal

Establish `xcodebuild Debug` as the canonical foreground build lane for Anigma's macOS/native integration work, while retaining SwiftPM graph validators for architecture checks.

## Context

- The repo currently uses SwiftPM graph validators successfully
- Full `swift build`/`swift test` is blocked by a pre-existing `_NumericsShims` issue
- For Anigma's macOS/native stack, `xcodebuild Debug` is more operationally useful than raw `swift build`

## Proposed Solution

### Validation Lane Hierarchy

| Priority | Lane | Purpose | Tool |
|---|---|---|---|
| Primary | Product/runtime build | macOS app/daemon with Apple frameworks | `xcodebuild Debug` |
| Secondary | Architecture graph | Dependency cycles, tiers, exports | SwiftPM describe + validators |
| Tertiary | SwiftPM build | Package-level compilation | `swift build` / `swift test` |

### Script: `Scripts/validate_xcodebuild_debug.sh`

```bash
# Usage
bash Scripts/validate_xcodebuild_debug.sh [--scheme <scheme>] [--test] [--dry-run]

# Default: builds anigma-app scheme in Debug
bash Scripts/validate_xcodebuild_debug.sh

# Build a specific scheme
bash Scripts/validate_xcodebuild_debug.sh --scheme anigmad

# Run tests
bash Scripts/validate_xcodebuild_debug.sh --test

# Dry run (print command only)
bash Scripts/validate_xcodebuild_debug.sh --dry-run
```

**Features:**
- Strict bash mode (`set -euo pipefail`)
- Repo-root detection
- Supports workspace (`package.xcworkspace`)
- Uses Debug configuration
- Uses stable DerivedData path (`.build/xcode-derived-data`)
- Prints exact xcodebuild command
- Returns nonzero on build failure
- Writes logs to `.build/logs/xcodebuild-debug.log`

**Destination:** `platform=macOS,arch=arm64`

### Command Template

```bash
xcodebuild \
  -workspace anigma/.swiftpm/xcode/package.xcworkspace \
  -scheme <scheme> \
  -configuration Debug \
  -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath .build/xcode-derived-data \
  build
```

### Test Command Template

```bash
xcodebuild \
  -workspace anigma/.swiftpm/xcode/package.xcworkspace \
  -scheme <scheme> \
  -configuration Debug \
  -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath .build/xcode-derived-data \
  test
```

## Doctrine

1. **xcodebuild Debug is the product/runtime build lane** - For macOS apps using Apple frameworks (Metal, CoreVideo, AVFoundation, etc.), Xcode schemes capture the actual product configuration including entitlements, signing, and platform-specific settings.

2. **SwiftPM validators remain the architecture graph lane** - `swift package describe --type json` + validation scripts check dependency cycles, tier compliance, and contract purity regardless of build system.

3. **swift build is useful but secondary** - Package-level compilation is valuable but may not represent the full macOS app/runtime lane.

## Decision Gate

The key question is:**Does `_NumericsShims` block xcodebuild Debug?**

- **If NO:** _NumericsShims is a SwiftPM/tooling cleanup task (lower priority)
- **If YES:** _NumericsShims is a real foreground blocker

This task will answer that question definitively.
